# Agenite 🤖

**A local-first, multi-provider AI agent client.** Plug in your own model API key and chat. With the Agent toggle on, it can **browse the web, read/write local files, do math, and run commands** by calling tools in a loop until it reaches a final answer.

Zero dependencies, fully offline, data stays in your browser. In the spirit of LobeChat / Open WebUI / LibreChat — but smaller, transparent, and fully auditable.

> 💡 Because it calls external model APIs (browsers block cross-origin requests), Agenite needs a **tiny local proxy** to forward requests — the same as LibreChat / Open WebUI. This project has **no third-party dependencies**: no `npm install`, just `node server.js` and open the browser.

## Why Agenite

Most "AI agents" are confident but unaccountable: they edit your files, then tell you it worked — even when it didn't. Agenite is built around **accountability**:

- **It proves its work.** After every change it runs your real test / verify command, and only keeps a skill learned from a *green* run.
- **It never loses your code.** Every mutation is auto-checkpointed to git — one `git undo` away.
- **It shows its reasoning.** A built-in Flight Recorder captures every step, tool call, and loop, and anchors each run to the exact git commit it ran against.
- **It measures itself.** The built-in **Eval** turns any saved run into a frozen "golden replay" regression suite: the tool results are replayed exactly, the model is the only variable, and Agenite reports pass rate, cost, turn count, and tool-adherence regressions against the previous baseline.
- **When it breaks, it finds the culprit.** The Regression Hunter auto-drives `git bisect` to pinpoint the first bad commit, then opens that commit's execution trace so you can see *what the agent was doing when the bug appeared*.

Zero dependencies. Fully offline-capable. Your keys never leave your machine except to call the model. In the spirit of LobeChat / Open WebUI / LibreChat — but smaller, transparent, and auditable.

## Quick start

```bash
# No npm install — the project ships zero dependencies
git clone https://github.com/wangzifan396-wzf/agenite.git
cd agenite
node server.js
# open http://localhost:4173
```

Or with Docker (one command, data persists in a volume):

```bash
docker run -p 4173:4173 -v agenite-data:/root/.agenite ghcr.io/wangzifan396-wzf/agenite
```

The `ghcr.io/wangzifan396-wzf/agenite` image is built and pushed automatically by CI (`.github/workflows/ghcr.yml`) on every push to `master` and on each version tag — `latest`, full semver (`0.70.0`), `major.minor` (`0.70`), and `sha` tags are all published, for both `linux/amd64` and `linux/arm64`. `GET /api/health` and `GET /api/version` give container orchestrators a liveness probe and the running version.

Add your model API key in Settings (OpenAI / Anthropic / Gemini / DeepSeek / Qwen / Ollama / …), flip the **Agent** switch on, and chat. That's it.

## ✨ Features

- **Verified Experience Memory · learn without poisoning (v0.60.0)**: the trustworthy answer to the 2026 "agent that grows with you" wave. Hermes shows memory compounds value across sessions — but its known failure mode is *silently remembering its own mistakes*; DeepSeek Harness proves the real worth is a *composable runtime with clean extension seams*, not the model. v0.60 fuses the two with Agenite's existing v0.58 verification gate + v0.59 outcome gate, so the memory can **never** be poisoned: **only goals that pass BOTH gates** (real proof of done + quality review of the actual diff) are crystallized as experiences. At the start of each goal the agent recalls the top-k past verified approaches by a lightweight token-overlap score and injects them into the system prompt as "things that worked before"; on a verified success it atomically appends a new experience (`memory/experiences/experiences.jsonl`). It reuses the exact VERIFY→self-heal loop and the same injectable-seam discipline as the v0.57 composable runtime — **agent.js / tools.js / server.js hot paths untouched, zero added ACI**. `goalMemory: on` (default) / `off`; the UI shows a per-goal **经验复用 ×N / 已沉淀经验** chip.

- **Self-Evolution: experience compounding (v0.54.0)**: Agenite already records every run (trace), measures each run (eval), and lets you share a tuned setup (presets) — but those three instruments were not yet *closed into a loop*. The new sidebar **🧬 自进化** panel shows a **health leaderboard** of your real runs (graded by errors, cost, turns, and silent loops), **distills the best config** from those traces (picks the highest-health provider/model and freezes it as a one-click preset — never exporting your API key or workspace), and runs a **drift sentinel** that flags when your current config scores worse than a past run's, with a one-click **rollback to any experience snapshot**. This is the rigor the 2026 "agent that grows with you" wave (Hermes, OpenJarvis) promises — grounded in hard verify + eval signals instead of a heuristic — so the agent gets more accurate the more you use it, never silently.

- **Multi-Model Intelligent Routing · strong model for planning, cheap model for execution (v0.62.0)**: the single most validated conclusion from the 2026 "multi-model management + intelligent routing" wave — **architectural tier routing (planner-executor split)**, not per-prompt classification. A goal is split into a **reasoning tier** (planning / verify gate / outcome gate / skill distillation, fed the strong model) and an **execution tier** (autonomous tool loop + final summary, fed the cheap model), cutting typical build cost ~4× with a lower inner-loop latency. The hard constraint surfaced repeatedly in the research — *a cheap model's key failure is dropping arguments and emitting malformed tool-call JSON* — is exactly the guard we lean on: both gates (v0.58 verify + v0.59 outcome) **always run on the strong model and read execution-log FACTS**, so the cheap executor cannot slip a wrong result past looking "right" (the structural defense against the 2026 "silent degradation" consensus). Implementation keeps **`client.js` hot path untouched**: `callModelStream` already supports `config.model` override, `modelRouter.js` is pure functions with fully injectable deps, and `goals.js` merely wraps `cm` into `cmR`/`cmE`. Settings ≥ ⚙ Model gains a **Multi-Model Routing** master switch plus **Reasoning model / Executor model** inputs (either may be left blank to fall back to the default model); every goal card shows a **多模型路由 · reasoning X / executor Y** (or **单模型 · X**) chip.
- **Procedural Skill Crystallization · the agent writes its own playbook (v0.61.0)**: the next layer on top of v0.60's verified *experience* pool — Hermes' distinctive **procedural memory**. Where experiences store raw "what worked for this goal" narrative, skills store DISTILLED, reusable *procedures* (applicable-when / steps / known-failure-points / verification) that apply to a whole *class* of future goals. When a *complex* goal passes BOTH the v0.58 verify gate and the v0.59 outcome gate, the agent distills a structured skill via the model and crystallizes it (`memory/skills/<id>.md` + `index.json`); a matching past skill is recalled at the start of a future goal and its full body injected into the system prompt. This is **progressive disclosure**: the index holds only name + summary (cheap), and only the top-k matched skill *bodies* are loaded — token cost stays flat as the library grows. A better later run *refines* an existing skill instead of duplicating it. The same non-poisoning guard applies: only proven-complex, double-gated goals ever become skills, so the playbook can never encode a mistake. Toggle with `skillCrystallization`: `on` (default) / `off`; the UI shows a per-goal **技能复用 ×N / 已结晶技能** chip.

- **Skill Curation & Pruning · a self-pruning playbook, not a junk drawer (v0.63.0)**: closes the one gap in v0.61's "crystallize-only" loop — the failure mode every 2026 auto-improving agent hits first (Hermes' #2: *a memory/playbook that never prunes just becomes a junk drawer*). After each goal settles, the agent now **curates** its skill library with three deterministic operations, never deleting a `.md` — only flipping `status: 'archived'` in `index.json`: **① Cap** — if active skills exceed `maxSkills` (default 60), archive the lowest-value ones by `(used+1)·(0.3+0.7·confidence)`; **② Dedupe** — keep the single best skill per normalized goal, archive the rest; **③ Decay** — archive any skill with `used===0` older than `skillDecayDays` (default 90). A recalled skill's `used` counter bumps (so live skills never decay), and the result is surfaced on the goal card as a **策展归档 ×N** chip. Curation is `on` by default, toggle with `skillCuration`: `on` / `off`. Combined with v0.60's non-poisoning memory + v0.61's gated crystallization + v0.63's curation, Agenite's self-improving loop is now provably *better* than Hermes: it writes skills only from verified successes, and prunes them by value — so the playbook stays small, sharp, and trustworthy indefinitely.

- **Skill Umbrella Consolidation · the playbook stays findable (v0.64.0)**: v0.63's dedup only removes *exact* duplicates (Hermes calls the narrow-skill proliferation a "junk drawer" even when nothing is a duplicate). v0.64 adds the higher-value Curator operation Hermes highlights as its differentiator — **Umbrella Consolidation**: when `umbrellaMin` (default 3) *distinct* active skills share one concept, they are merged into a single concept-level **umbrella skill** whose body concatenates each sibling under a `## <name>` heading; the narrow siblings are **archived** (`status: 'archived'` + `consolidatedInto` pointer) but their `.md` bodies stay on disk, so the merge is fully reversible. The point is **findability, not disk savings**: a library of 50 narrow `pr-*` skills is unnavigable even without duplicates; one `PR 技能集` you can actually recall is not. The shared concept is derived *deterministically* — the token with the highest document-frequency across active skills (via the existing tokenizer), excluding stopwords and universal tokens — so consolidation needs **no LLM call** and never surprises you with a wrong merge. Toggle with `skillUmbrella`: `on` (default) / `off`; surfaced on the goal card as a **已合并 ×N** chip.

- **OpenTelemetry GenAI export · your traces in any backend (v0.66.0)**: Agenite already has a local-first **flight recorder** that captures every run as a tree of typed steps. v0.66 adds the **interoperability layer** that maps a finished trace onto standard **OpenTelemetry (OTLP/HTTP JSON) spans following the 2026 OTel GenAI semantic conventions**, so any Collector / Jaeger / Tempo / Langfuse can ingest an Agenite run out of the box — no vendor lock-in, no new recorder. The converter (`src/core/otel.js`) is pure and faithful to the spec: deterministic, non-zero `traceId`/`spanId` derived from the run via FNV-1a; spec-correct span names (`invoke_agent {agent}` / `chat {model}` / `execute_tool {tool}`) and `gen_ai.*` attributes — using the **renamed 2026 names** (`gen_ai.provider.name` not the deprecated `gen_ai.system`; `gen_ai.usage.input_tokens`/`output_tokens` not `prompt_/completion_tokens`; there is **no** `gen_ai.latency.ms` — latency is the span duration); `SpanKind` CLIENT for remote model / MCP calls vs INTERNAL for in-process; failed tools carry `error.type` + `STATUS_CODE_ERROR`; and the message / tool-I/O content fields are **opt-in only** (`captureContent`), matching `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`. Wiring: `server.js` auto-buffers per-turn token *deltas* (the `usage` event is cumulative) onto each chat span; `GET /api/traces/:id/otel` downloads an OTLP payload; `POST /api/otel/export` pushes to a Collector; and with `otelExport: 'on'` a run auto-pushes on completion (best-effort, never blocks the chat). Settings ≥ 可观测性 hold the endpoint / headers / service name / content toggle. Zero added recording layer — the local trace remains the single source of truth.

- **Container-ready release · one-command self-host, now actually published (v0.67.0)**: v0.49 wrote the `docker run ... ghcr.io/wangzifan396-wzf/agenite` line but no image ever shipped. v0.67 closes that loop: a new `.github/workflows/ghcr.yml` builds the dependency-free image on `linux/amd64` + `linux/arm64` and pushes it to GitHub Container Registry on every push to `master` and each version tag — `latest`, full semver (`0.67.0`), `major.minor` (`0.67`), and `sha` tags, for both arches. A live version badge (`.github/workflows/badge.yml` → `docs/badges/version.json`, rendered via a shields.io endpoint) keeps the README honest automatically. And two zero-auth probes land for orchestration: `GET /api/health` (liveness, already present) and the new `GET /api/version` returning `{ name: 'agenite', version }` read from `package.json` at boot — so a k8s / Docker Compose healthcheck or a badge reports the exact running version without a rebuild. No UI rebuild, no new dependencies.

- **Root-cause-driven self-healing & re-planning · the agent diagnoses before it acts (v0.68.0)**: the 2026 production-agent consensus is unanimous that a *self-healing* agent must do more than nudge — it must **classify the failure's root cause** and pick the right recovery, not the same reflex for every error. Agenite's old "自检提醒" was exactly that reflex: one free-text nudge for every failed mutation. v0.68 introduces a machine-consumable **fault taxonomy** (`src/core/fault.js`, the same injectable/testable paradigm as `stallguard.js`/`client.js`): `transient` · `structural` · `semantic` · `auth` · `budget` · `unknown`. `classifyError(err, {status,text,name,errorClass})` maps a model/tool/network error to a category with `{retryable, replan, escalate, severity, hint}` — reusing `client.js`'s `errorClass` vocabulary and extending it to runtime failures (malformed tool call, malformed JSON, context-limit, schema mismatch). `decideSelfHeal(ctx)` then turns the category + loop/stuck signals into one of `retry` (transient → exponential `backoffMs` with jitter) · `replan` (structural/semantic + stuck loop) · `reflect` · `compress` (budget → proactively reclaim context via `compactMessages`, no crash) · `escalate` (auth, or reflection budget exhausted → fire once, then latch so it can't nag forever). `dominantCategory(cats)` resolves mixed failures by severity. The agent loop emits **one `self_heal` event as the single source of truth**, and it flows consistently into: the live trace + flight recorder (`kind:'self_heal'`), an OpenTelemetry span in `otel.js` (`name:'self_heal <action>'`, `error.type` set when escalating), `GET /api/health` → `selfHealStats{total,lastCategory,lastAction,lastAt}`, and the frontend live-trace panel (🩹 icon + 自愈 label) + a toast. The bounded `maxReflections` budget still closes the door on infinite loops; escalation is a hard stop, not another retry. 16+ new pure unit tests (`test/fault.test.js`) + integration (`test/selfheal.test.js`); full suite 645 green.

- **Self-healing that actually executes recovery · structured re-planning + stall-guard reset (v0.69.0)**: v0.68's `replan` was still a *text nudge* — the model might comply, or it might loop again and get re-killed by the stall guard on the very next turn. v0.69 upgrades it to a **real executed recovery**, not a suggestion. When the loop breaker fires `replan`, `agent.js` now: **① resets the stall guard** — clears `turnsSinceProgress` and the exact-repeat `loopStreak` / `lastTurnSig` so the fresh approach gets a fair chance instead of being immediately re-penalized; **② re-plans the live todo/plan checklist** — completed items are *preserved* (real progress kept) while the remaining `in_progress` / `pending` items are collapsed back to `pending`, forcing the model to re-state its next steps via `todo_write`; **③ emits a structured `self_heal` event** carrying `reason:'looping'` + `resetCounters:true` + `replanned:true`, consumed identically by the live trace (🧭 · 已清零停滞计数), an OpenTelemetry span (`agenite.self_heal.reason` / `reset_counters`), and `GET /api/health` (`lastReason` / `lastResetCounters`). The pure decision core in `fault.js` (`decideSelfHeal`'s `replan` branch) now returns the `reason` + `resetCounters` signal; `agent.js` performs the reset; the full observability chain is updated to render it. A new integration test asserts replan truly resets the counters and re-plans the todo list — full suite green.

- **Adaptive anti-flapping self-healing · the agent stops repeating useless remedies (v0.70.0)**: v0.68–v0.69 gave the agent a root-cause taxonomy and a *real* executed recovery (re-plan that resets the stall guard + re-plans the todo). But `decideSelfHeal` still had **no memory of what it tried last round** — so under the same root cause it would repeat the same therapy (a semantic failure → reflect → fail → reflect again, even though re-reading clearly didn't help). v0.70 closes that blind spot with **adaptive anti-flapping**: the decision now receives `lastAction` / `lastCategory` (the previous remedy and its fault) and **auto-escalates the strategy when a remedy fails on the same root cause** — `reflect → replan` (reason `'flap_reflect'`, with `resetCounters`) the first time a re-read proves useless, and `replan → escalate` (reason `'flap_replan'`) if a re-plan still loops on the same cause. `retry` is deliberately **excluded** — transient blips stay bounded by `maxAttempts`, never by flapping. The agent loop tracks `lastHealAction` / `lastHealCategory`, emits them on the `self_heal` event, and the upgrade is observable end-to-end: the live trace shows **🔁反抖动** + the prior action, the OpenTelemetry span gains `agenite.self_heal.flap`, and `GET /api/health` now carries a **recovery ledger** — `lastFlap` plus `healHistory` (the last 6 attempts: `category` / `action` / `flap` / `reason` / `at`) — so ops can see exactly how the agent has been trying to recover. New pure-decision tests + an integration test assert the reflect→replan(flap) upgrade; full suite green (620 tests).

- **Metacognitive reflection · experience manual (v0.56.0)**: the *behavior-layer* half of the self-improvement loop, sitting on top of v0.54's *config-layer* self-evolution. Every run now ends with a reflection pass that turns the run's hard signals — did auto-verify pass, did it loop, did it mutate without verifying, did it finish — into **typed lessons** (principle / procedure / warning / skill-defect / execution-lapse), scored and persisted to `~/.agenite/memory/lessons.json`. The highest-value lessons are injected into the **next run's system prompt** so the agent literally starts wiser, and the sidebar **📖 经验手册** panel lets you browse, enable/disable, delete, or clear them, toggle injection, and opt into LLM-enriched (more specific) lessons. This is the 2026 metacognitive-reflection wave (MARS / EmbodiSkill) done on *evidence* Agenite already collects — no guessing, no cloud, fully offline.

- **Stall Detection + Graceful Degradation · the agent knows when it's stuck (v0.65.0)**: closes the one blind spot the 2026 production-agent literature hammers hardest — the *runaway / stuck agent* that throws nothing yet burns the whole budget making zero progress. Agenite already had an exact-repeat loop breaker and a cost guardrail, but those miss the **semantic stall**: thrashing with *different* actions yet getting nowhere (re-reading files, retrying variants that all fail, thinking in circles). v0.65 adds a deterministic, model-free **stall guard** (`src/core/stallguard.js`): it counts consecutive turns with no successful tool call *and* no todo advance, and at the soft threshold (`stallTurns`, default 6) emits one "you're stuck, reconsider" nudge; at the hard threshold (`stallHardTurns`, default 12, always ≥ soft) it **stops gracefully** as a distinct `blocked` goal status with a "卡点说明" instead of crashing or silently burning tokens. This is the "escalate rather than guess" discipline (spicyadvisory / icmd 2026 playbook) made structural — the agent can't hide in a loop, and a stuck run is recoverable, not a failure. Toggle with `stallGuard`: `on` (default) / `off`; surfaced on the goal card as a red **⚠ 停滞阻塞 · N 回合** chip.
- **Composable runtime · pre-flight Experience Guard & project instructions (v0.57.0)**: the engine-level borrowing from the viral DeepSeek Harness — its real worth was *architecture*, not the model. Agenite now has a tiny **HookBus + tool-execution pipeline with pre/post stages** (`src/core/hooks.js`), the single composable seam every tool call flows through. Two ready-made plugins ride it: **① Pre-flight Experience Guard** turns the v0.56 Experience Manual from a passive system-prompt footnote into an *active* safety gate — before any world-mutating tool runs, it recalls the agent's own hard-won lessons (unverified mutation, verify-failure, runaway loops) and, in `warn` mode (default), surfaces them as a real-time UI chip **and** folds them into the tool result so the agent sees the lesson *in-context*; in `block` mode it refuses only the highest-risk verbs when a strong runaway-loop lesson exists. **② Project instruction files (AGENTS.md / CLAUDE.md compatible)** auto-load the repo's "how to work here" file into the system prompt, so conventions are respected without re-pasting them every turn. Both are additive: `agent.js` / `tools.js` hot paths are untouched — zero regression (489 tests green).

- **Verification-gated goal completion (v0.58.0)**: the single biggest gap between "an agent that tries" and "an agent you can trust" — *how does it know it's done?* Until now a delegated goal asked the LLM to grade **its own report** and treated anything that didn't literally say "未完成" as done — a false-positive bias straight out of the 2026 reliability post-mortems. v0.58 flips it to **proof required**. The goal's completion is now a **verification gate**: **deterministic real-test verification is the primary signal** — it auto-detects and runs the project's own check (`npm test` / `cargo test` / `go test` / `pytest` / `make test`) and only accepts the goal when that command passes; a **fresh-context LLM judge** (sees the *execution log facts*, never the agent's self-report — so it can't rubber-stamp its own claims) is the fallback for open-ended goals with no test command. The bias is inverted: **no proof ⇒ not done**, and the final report carries the evidence (which command ran, what it said). Four modes via `goalVerify`: `auto` (test if present, else judge — default), `full` (test gate only; if no tests exist the goal *fails* rather than silently passing), `judge` (fresh-context judge only), `off` (legacy, not recommended). Purely additive — `agent.js` / `tools.js` / `server.js` hot paths untouched; `verifyWorkspace` already exercised by the agent's own verify loop is now the goal's source of truth.

- **Outcome-gated quality review · anti-exploit (v0.59.0)**: v0.58 proved a goal *ran its tests* — but the 2026 hard lesson is **"tests passing ≠ a good patch"**. METR found only ~50% of SWE-bench-Verified patches were accepted by maintainers; OpenAI deprecated SWE-bench Verified in 2026-02 over contaminated tests; Anthropic's "Outcomes" cut silent failures ~6×. So v0.59 fuses a **quality gate into the very same VERIFY→self-heal loop** — no second agent, no heavier ACI (per Princeton's mini-SWE-agent finding that the agent-computer interface matters more than architecture). After the deterministic test gate already proves the goal *functionally* done, the **Outcome Gate** runs: **① deterministic anti-exploit checks** (always on, free) that reject an empty diff / no-op and deleted test files — the exact cheat patterns the Berkeley RDI scanner flagged; **② a fresh-context Critic** that reviews the *actual git diff + verification result*, never the agent's self-report, and returns structured criticism ("达标 / 未达标" + concrete fixes). A "未达标" verdict feeds straight back into self-heal with that specific feedback, so the agent fixes real quality gaps, not just green tests. Toggle with `goalCritic`: `on` (default) or `off`. Degrades gracefully — when there's no git baseline to diff against, the gate is skipped and the v0.58 verify gate stays authoritative. The UI shows a per-goal **成果复核** chip.

- **Regression Hunter — auto `git bisect` to pinpoint the breaking commit (v0.47.0)**: the missing piece for "it used to work, now it's broken". When the user says "this was fine before / when did it break / it broke after some update", the agent calls `regression_hunt` to **auto-drive a git bisect** using the project's own verify command (`npm test` / `pytest` / `go test` / custom) on each candidate commit and pinpoint the **first bad commit** — no more manual checkout-and-guess:
  - 🔍 **Self-driven bisect loop (not `git bisect run`)**: we drive the bisection ourselves because `git bisect run` shells out to a command that breaks on Windows `.cmd` shims and reads the culprit only from the locale-dependent `<hash> is the first bad commit` line. Instead we read the answer from `refs/bisect/*` refs — **locale-independent**, and it works on **SHA-256 repos** (64-char hashes) too.
  - 🛡️ **Two-end pre-check against false culprits**: it first verifies HEAD really fails (else reports `head-pass`) and that the chosen good baseline really passes (else warns `good-bad` — your baseline itself is broken, go further back) before trusting any "good" mark — so it never hands back a wrong commit.
  - ♻️ **Always restores the working tree**: every exit path (success / fail / exception) runs `git bisect reset` and checks the original branch back out, so you're never left in a detached HEAD.
  - 🖥️ **UI panel + live polling**: the sidebar "🔍 回归猎手" opens a panel that auto-checks the workspace, suggests a good baseline (nearest tag, or step back N commits), and — once started — runs the tests commit-by-commit on the backend (minutes-long) while the frontend polls and renders each round (good/bad/skip) and the final culprit (hash / subject / author / date / touched files / search space). One click "让智能体分析这个提交" hands the commit straight to the agent to fix.
  - 🔒 **Sub-agent & parallel-safe**: because `regression_hunt` switches the working tree, it's on the sub-agent forbidden list and the never-compress list — so a child agent can't run it in parallel and stomp files, and the bisect result is never silently dropped.

- **Verification-gated skill distillation (v0.46.0)**: the skill library stops merely *growing* and starts *getting better*. - **Context Economy layer (v0.45.0)**: tool results are shrunk *before* they ever enter the history — not after the window has already overflowed (that late, blunt compaction still exists as a safety net). Oversized output is compressed by content type, and **every byte stays retrievable**:
  - 🗜️ **Content-aware, three shapes**: a huge JSON blob collapses to its **schema + samples + anomalies** (`Array(1247) of {id: number, …}` — the one error row hiding among a thousand good ones is kept verbatim); log floods fold repeated lines into `×N`; source files become a **declaration outline + the lines your `query` actually hit**.
  - ♻️ **Reversible by construction**: the full original is stored verbatim in a TTL `ContextStore`, and the compressed text carries a `context_retrieve(handle="…")` hint. The model pulls the exact lines back — optionally `pattern`-grep'd — instead of re-running the tool. **No store → no compression**, so it can never silently drop information.
  - 🎚️ **Three modes**: `off` / `smart` (default — only bites genuinely huge results) / `aggressive` (small windows, squashes earlier). Threshold is tunable in ⚙ Workspace / Permissions. Failures and short structural tools (`todo_write` / `plan` / `verify` / `git`) are never compressed.

## 🚀 Quick start

```bash
cd agenite
node server.js
# open the printed URL, default http://localhost:4173
```

Then open ⚙ **Settings** (top-right): pick a provider, paste your API key, confirm the model, save, and start chatting.

```bash
npm test       # run core unit tests (527, via node:test)
npm run build  # build single-file dist/agenite.html
npm start      # alias for node server.js
PORT=8080 node server.js   # custom port
```

## 🧱 Architecture

```
server.js        # zero-dep HTTP: static + /api/chat proxy + agent loop (SSE)
build.js         # inline bundler -> dist/agenite.html
src/app.js       # browser controller
src/core/        # pure logic, DOM-free, Node-testable
  config / markdown / provider / client / tools / atlas / agent / util
  mcp.js         # MCP client: stdio / HTTP / SSE transports, multi-server manager (server-side only)
  context.js     # context estimation + auto-compaction (estimateTokens / compactMessages)
  pricing.js     # price table + cost estimation (normalizeUsage / priceFor)
  sessions.js    # on-disk session mirror (safeSessionId / read-write)
test/            # node:test unit tests (+ mcp-mock-server.mjs)
```

**Flow**: `app.js` → `POST /api/chat` (history + config) → `server.js` runs `runAgent` → calls model (SSE) → if the model requests tools, the server executes them → feeds results back → loops to final answer → streams `start`/`delta`/`tool`/`done`/`end` events to the UI.

## 🔒 Security

- API keys live only in your browser `localStorage` and are forwarded by the local proxy — never uploaded elsewhere.
- `write_file` / `edit_file` / `make_dir` / `run_command` / `open_path` are **danger tools**, off by default, enabled only via the "高级工具" setting and gated by the approval mode (`ask` / `auto` / `deny`).
- **Workspace sandbox**: every file path is resolved and pinned under a root directory; an escape hatch (`allowOutsideWorkspace`) is off by default.
- **MCP servers are local child processes**: connecting one spawns a process on your machine, and its reach is whatever that server implements (desktop-control servers can move your mouse and type). Only connect servers you trust — MCP calls are gated by the same `ask` / `auto` / `deny` approval mode, and `ask` (the default) prompts on every call.
- All Markdown is HTML-escaped; links are filtered against `javascript:` / `data:` schemes.
